# --- shadow-dom/declarative -------------------------------------------------
#
# 7,731 of 7,791 as of 2026-08-12, from 114. What is left is three causes and
# none of them is declarative shadow DOM:
#
#   * **Six subtests need a script to run *during* the parse.** Each one puts an
#     inline `<script>` inside the `<template shadowrootmode>` so that a
#     MutationObserver fires while the template is still open, then asserts on
#     what the tree looked like at that instant. This parser builds the whole
#     document and runs scripts afterwards (ADR 0030), so the observer sees the
#     finished tree. The *final* tree is right in every one of them -- these are
#     the six below plus declarative-with-disabled-shadow, innerhtml-*,
#     move-template-before-closing-tag and script-access.
#   * **Two need nested browsing contexts** (ADR 0027): declarative-shadow-dom-opt-in
#     ends in four `<iframe>` async_tests, and declarative-shadow-dom-write-to-iframe
#     is `document.write` into one.
#   * **Thirty-four are tentative/shadowrootadoptedstylesheets**, which is HTML
#     PR 12339: `shadowrootadoptedstylesheets="foo"` resolved through an *import
#     map* against CSS module scripts, with `modulepreload`. That needs the
#     module loader (still unbuilt, see CLAUDE.md) plus CSS module scripts, and
#     it is an unshipped proposal on top. Six of that suite *do* pass -- the
#     attribute reflects, is kept verbatim and round-trips through `getHTML` --
#     because those halves are complete on their own and an unresolvable
#     specifier is specified to be skipped silently, which is every specifier
#     until an import map exists to resolve one against. `adoptedStyleSheets`
#     stays empty, which is the right answer and not an approximation.
